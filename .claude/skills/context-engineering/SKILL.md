# /context-engineering — Проектирование контекста для агентов

## Когда использовать
- Настройка нового агента или скилла под свою роль
- Агент работает плохо / галлюцинирует — диагностика причин
- Проектирование своего `CLAUDE.md` (или правка `COMPANY.md`/`AGENT-PERSONALITY.md`)
- Оптимизация расходов на токены без потери качества

## Почему это важно

Агент = модель + контекст. Модель фиксирована. Контекст — это всё, что ты контролируешь.
Плохой контекст → плохие ответы, даже с лучшей моделью.
Хороший контекст → правильные ответы с дешёвой моделью.

Context Engineering = дисциплина проектирования того, что именно попадает в контекст агента.

## 6 измерений AI-автономии (методология Байрама Аннакова, из M0-аудита)

| Измерение | Вопрос | Было | Цель |
|-----------|--------|------|------|
| **Time to Insight (TTI)** | Сколько от вопроса до ответа? | дни/часы | минуты |
| **Task Automation** | Какие повторяющиеся задачи автоматизированы? | 0-10% | 50-80% |
| **Knowledge Retention** | Где хранятся знания команды? | в головах | в базе |
| **Quality Control** | Как оценивается качество AI-вывода? | вручную | автоматически |
| **Parallel Capacity** | Сколько задач одновременно? | 1-3 | 10-20 |
| **Onboarding Speed** | Сколько учится новый сотрудник? | 2 недели | 1 день |

Это те же 6 осей, по которым тебя уже оценили на M0 (см. свою карточку в аудите) — этот скилл про то, как двигать их вперёд самому, а не только знать текущий балл.

## Правила контекста (что грузить, что нет)

### ГРУЗИ в контекст:
- `CLAUDE.md` / `COMPANY.md` — инструкции и правила (читается первым)
- `AGENT-PERSONALITY.md` — как агент должен вести себя конкретно с тобой
- Конкретные файлы, нужные для ЭТОЙ задачи
- Релевантные примеры (few-shot)
- Критерии оценки результата

### НЕ ГРУЗИ:
- Всё подряд "на всякий случай" — раздуваешь контекст, снижаешь качество
- 50 сообщений из переписки — бери 10 релевантных
- Все файлы проекта — только нужные для задачи
- Историю прошлых сессий — пиши в файлы (`notes/`), не держи в чате

### Правило Байрама по токенам:
- Русский текст ≈ 1.5x токенов vs английский
- Свои шаблоны/инструкции для агента — писать компактно, без воды
- `CLAUDE.md`/`COMPANY.md` не должны подгружать ВСЕ файлы при каждом запросе — только то, что нужно почти всегда

## Структура хорошего рабочего файла (CLAUDE.md / COMPANY.md)

```markdown
# [Роль] — рабочее пространство

## Startup (только то, что нужно почти всегда)
- COMPANY.md — роль, метрика, обязательные правила
- AGENT-PERSONALITY.md — как агент ведёт себя со мной

## Context (статичное, не меняется)
- Роль, метрика, ключевые задачи

## Rules (поведение агента)
- Конкретные правила, не общие пожелания
- Каждое правило = одно действие

## Current Priorities (меняется редко)
- Топ-3 приоритета из твоей матрицы M0, не больше
```

## Диагностика плохого агента

| Симптом | Причина | Лечение |
|---------|---------|---------|
| Галлюцинирует факты | Нет источников в контексте | Добавь реальные данные, не полагайся на память модели |
| Игнорирует инструкции | `COMPANY.md`/`AGENT-PERSONALITY.md` слишком длинный | Сократи, оставь главное |
| Теряет нить задачи | Слишком большой контекст за один раз | `/harness` (M2) — разбей на шаги |
| Отвечает шаблонно | Нет примеров в контексте | Добавь few-shot примеры своей реальной работы |
| Слишком дорогой | Лишние файлы грузятся каждый раз | Отфильтруй, оставь только нужное для текущей задачи |

## Применение в своей работе

Возьми свой приоритетный процесс из `process-tracker.md` (тот, который автоматизируешь по программе) и спроси себя:

- **Что должно грузиться почти всегда** (роль, метрика, правила компании) — держи в `COMPANY.md`
- **Что грузится только под конкретную задачу** (данные одного кандидата, один клиентский кейс) — не тащи это в постоянный контекст, подавай точечно
- **Что вообще не нужно AI** (вся история переписки, все прошлые кейсы разом) — не грузи "на всякий случай"

Пример: если ты работаешь с кандидатами — в контекст идёт методология оценки + критерии роли, но НЕ все резюме, которые ты когда-либо смотрел. Если готовишь фидбек сотруднику — в контекст идут его конкретные результаты, но НЕ вся история компании.
